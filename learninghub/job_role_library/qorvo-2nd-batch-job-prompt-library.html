Role-Based Webpages + Build Prompts

A curated set of webpage concepts aligned to the participant roles in the second Qorvo SFDW 2.0 batch — each role gets copy-paste prompts that produce working internal tools, each one replacing 3 common Excel files and 2 recurring emails in the daily work of planning, testing, sourcing, accounting for and selling RF and power semiconductor products.

🎯 8 job functions
👥 22 participants
⚡ 23 build prompts

How to use this guide

Find the section matching your job function, then copy any build prompt straight into an AI tool — Microsoft Copilot, ChatGPT, Claude, or Gemini. Each function offers two to five tools — pick the one that speeds up the job you care about most. Every prompt is self-contained and produces a single HTML page with embedded CSS and vanilla JavaScript that you can preview in any browser and adapt to your team's actual data, and every prompt ends with an instruction to show the full HTML source code in the code console so you can copy it directly. This batch is weighted toward planning (seven planners) and test development (five engineers), so Production Planning carries five tools and Product & Test Development Engineering carries four; the specialist roles — layout and ESD, sourcing and procurement, regional finance and tax, business analysis and CSR, and inside sales — each get tools written for their own job. The framing throughout is the same: “Build a browser-based, personal productivity cockpit that replaces 3 common Excel files and 2 recurring emails in your job.”

💡 Prompt Tips

To get the best results from any of these prompts:

  • Paste the entire prompt into your AI tool in one go — don't trim it. The last line asks the AI to show the full HTML code in the console so you can copy it straight out.
  • Pick more than one — your function has two to five tools; build the one that saves you the most time first, then come back for the others.
  • After the first build, ask for iterations: “Add a dark mode toggle” or “Replace the seed data with my actual part numbers, suppliers, or customer list.”
  • If the output feels generic, add context at the end: “Use terminology familiar to an RF and power semiconductor assembly and test operation.”
  • Seven planners share the Production Planning section and five engineers share Product & Test Development — build different tools and swap the finished pages between you rather than all building the same one.
  • Keep company data out of the tool while you are learning — build with the seeded sample data first, then swap in real figures once the page runs locally in your own browser. Treat customer names, part numbers, yields, pricing, financials and tax positions as confidential.
  • Keep the unified framing in mind: each page should replace 3 common Excel files and 2 recurring emails in your job.
