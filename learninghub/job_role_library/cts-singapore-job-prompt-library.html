Role-Based Webpages + Build Prompts

A curated set of webpage concepts aligned to the participant roles in the CTS Singapore SFDW 2.0 class — each role gets copy-paste prompts that produce working internal tools, each one replacing 3 common Excel files and 2 recurring emails in the daily work of planning supply, buying materials, engineering products and processes, serving customers and accounting for the cost of sensors, actuators and electronic components.

🎯 7 job functions
👥 11 participants
⚡ 21 build prompts

How to use this guide

Find the section matching your job function, then copy any build prompt straight into an AI tool — Microsoft Copilot, ChatGPT, Claude, or Gemini. Each function offers two to four tools — pick the one that speeds up the job you care about most. Every prompt is self-contained and produces a single HTML page with embedded CSS and vanilla JavaScript that you can preview in any browser and adapt to your team's actual data, and every prompt ends with an instruction to show the full HTML source code in the code console so you can copy it directly. This class is weighted toward supply chain (a director and two analysts) and engineering (three senior engineers), so Supply Chain Planning carries three tools and Engineering carries four; procurement, customer service, and cost accounting and finance each get tools written for their own job, and the Director, Supply Chain gets a leadership view across the whole chain. The framing throughout is the same: “Build a browser-based, personal productivity cockpit that replaces 3 common Excel files and 2 recurring emails in your job.”

💡 Prompt Tips

To get the best results from any of these prompts:

  • Paste the entire prompt into your AI tool in one go — don't trim it. The last line asks the AI to show the full HTML code in the console so you can copy it straight out.
  • Pick more than one — your function has two to four tools; build the one that saves you the most time first, then come back for the others.
  • After the first build, ask for iterations: “Add a dark mode toggle” or “Replace the seed data with my actual part numbers, suppliers, customers or cost centres.”
  • If the output feels generic, add context at the end: “Use terminology familiar to an electronic components manufacturer serving automotive and industrial customers.”
  • The three senior engineers share the Engineering section and the two analysts share Supply Chain Planning — build different tools and swap the finished pages between you rather than all building the same one.
  • The tools connect: the shortage board (03) feeds the supplier chase in the PO tracker (06), which feeds the promise dates in the order book (13). Try building two and copying the output of one into the other.
  • Keep company data out of the tool while you are learning — build with the seeded sample data first, then swap in real figures once the page runs locally in your own browser. Treat customer names, part numbers, prices, costs, supplier terms and financials as confidential.
  • Keep the unified framing in mind: each page should replace 3 common Excel files and 2 recurring emails in your job.
